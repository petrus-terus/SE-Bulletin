Generated by the `improve-animations` audit workflow (recon → parallel subagents per category → vet). Commit at which these were written: `debeccb`. All findings were verified first-hand at their file:line before being turned into plans.

## Recommended execution order

Plans are written to run independently (no shared edits), but this order minimizes risk and gives fast wins first:

1. **001 — Mobile-native foundation** (HIGH) → do first: 12 one-line edits, zero risk to visuals, biggest behavior win (iOS zoom, Android keyboard, PTR). Requires real-device verification.
2. **002 — Carousel touch-action + scroll containment** (HIGH) → do right after 001: the same real-device pass can verify both.
3. **003 — Like-pop a11y parity** (HIGH) → a11y correctness, trivially small.
4. **004 — transition:all + token cleanup** (MEDIUM) → mechanical; run alone to keep the diff reviewable.
5. **005 — Toast exit phase** (MEDIUM) → the one TSX change; verify with build.
6. **006 — StoryViewer entrance** (MEDIUM/opportunity) → smallest visual add; do last or when polishing the demo.

## Dependencies

- **003** depends on nothing but being reviewed after 004's token cleanup for a clean diff.
- **001 and 002** overlap on the same real-device test session — do both before testing on hardware.
- 004, 005, 006 touch distinct files/features — fully parallel-safe.
